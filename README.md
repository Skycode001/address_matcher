# Общее описание

**Address Matcher** — высокопроизводительная система для поиска и нормализации адресов, разработанная для работы с существующей базой данных. 
- **Важно:** наличие специального файла хранилища адресов с названием "addresses.csv" в папке data
- Все операции проводятся на основе этого файла.

Система использует комбинацию методов:

1. **Нормализация адресов** с помощью:
   - Регулярных выражений
   - Словаря сокращений (50+ вариантов)
   - Фонетической нормализации
   - Специальных правил для корпусов, строений и размеров улиц
   - Реверса слов для улиц-исключений

2. **ML-модель** (логистическая регрессия) для ранжирования кандидатов:
   - 10 признаков с весовыми коэффициентами
   - Обучение на сбалансированной выборке

3. **Гибридный скоринг** с бонусами:
   - Совпадение номера дома (+30)
   - Совпадение микрорайона (+25)
   - Совпадение населенного пункта (+20)
   - Совпадение муниципалитета (+15)

4. **Многоуровневый поиск**:
   - Точный поиск по хэш-индексу
   - Нечеткий поиск через rapidfuzz
   - Специализированный поиск по округам (ТиНАО, ЗелАО)
   - Поиск по ключевым словам через индекс

5. **Фильтрация кандидатов** по:
   - Номеру дома (с учетом литер)
   - Корпусу и строению
   - Названию улицы
   - Цифровым последовательностям

6. **Кэширование** для ускорения повторных запусков:
   - Нормализованные адреса
   - Хэш-индекс
   - Автоматическая инвалидация при изменении кода

7. **Файловый режим** с обогащением данных:
   - Поддержка CSV и Excel
   - Автоматическое добавление ключевых слов по округу
   - Заполнение всех колонок из базы

## Ключевые характеристики

| Характеристика | Значение |
|---------------|----------|
| Размер базы | N* адресов |
| Скорость поиска | 50–100 мс |
| Время загрузки (с кэшем) | 2–3 секунды |
| Время загрузки (без кэша) | ~3 минуты |

- *Для количества адресов >500000

# Нормализация адресов
- Система нормализации адресов выполняет последовательную обработку входной строки, преобразуя её в канонический вид, пригодный для сравнения и поиска.

## Общая схема

```text
Вход:
"улица Исаковского, 33к4с1"

1.  Приведение к нижнему регистру
2.  Замена ё → е
3.  Удаление упоминаний "город Москва" (и его склонений)
4.  Реверс слов (при необходимости) — street_variants.py
5.  Обработка "пр-д" → проезд, "пр-кт" → проспект
6.  Обработка размеров (М. → малый, Б. → большой) в контексте
7.  Обработка порядковых числительных (1-й, 2-я)
8.  Перестановка: "парковая 15-я" → "15-я парковая"
9.  Явная обработка "д13" → "дом 13", "к2" → "корпус 2"
10. Разбор слитных форм: "17к2с2" → "17 корпус 2 строение 2"
11. Обработка "стр", "с" → "строение"
12. Обработка обратного порядка (строение → корпус → дом)
13. Удаление дублирующихся слов
14. Замена сокращений через словарь ABBREVIATIONS
15. Перестановка типа улицы в конец
16. Финальная очистка (лишние пробелы, точки)

Выход: "улица Исаковского, дом 33, корпус 4, строение 1"

```

# ML модель и расчет скоринга

### `generate_features(query, candidate)`

Функция генерирует 10 числовых признаков для сравнения двух адресов (запроса пользователя и кандидата из базы). Эти признаки используются ML-моделью (логистической регрессией) для ранжирования кандидатов и расчета вероятности совпадения.

**Место в коде:** `src/utils.py`

### Признаки и их веса в `hybrid_score`

| № | Признак | Вес | Описание | Формула / метод |
|---|----------|------|-----------|-----------------|
| 1 | `ratio_norm` | 0.20 | Схожесть нормализованных адресов | `fuzz.ratio()` после `normalize_address()` |
| 2 | `ratio_street` | 0.15 | Схожесть названий улиц | `fuzz.ratio()` после `extract_street_name()` |
| 3 | `token_sort_ratio` | 0.10 | Схожесть с сортировкой слов | `fuzz.token_sort_ratio()` |
| 4 | `partial_ratio` | 0.05 | Частичное совпадение | `fuzz.partial_ratio()` |
| 5 | `phonetic_ratio` | 0.05 | Фонетическое совпадение | `fuzz.ratio()` после фонетической нормализации |
| 6 | `prefix_match` | 0.05 | Совпадение начала названия улицы | Полное совпадение первых 5 символов или частичное сравнение первых 3 |
| 7 | `house_match` | 0.20 | Совпадение номера дома | 1.0 при полном совпадении, 0.7 при совпадении основного номера |
| 8 | `corpus_match` | 0.05 | Совпадение корпуса | 1.0 при совпадении наличия/номера корпуса |
| 9 | `length_ratio` | 0.05 | Сходство длины строк | `1 - abs(len(q) - len(c)) / max(len(q), len(c))` |
| 10 | `type_match` | 0.10 | Совпадение типа улицы | Совпадение типа (`улица`, `проспект`, `бульвар`, и т.д.) |

### Веса в `calculate_hybrid_score()`

В методе `calculate_hybrid_score()` используется следующий набор весов:

```python
weights = [
    0.20,  # ratio_norm
    0.15,  # ratio_street
    0.10,  # token_sort_ratio
    0.05,  # partial_ratio
    0.05,  # phonetic_ratio
    0.05,  # prefix_match
    0.20,  # house_match
    0.05,  # corpus_match
    0.05,  # length_ratio
    0.10   # type_match
]
```

Дополнительно применяются бонусы и штрафы:

```python
# Совпадение номера дома
modified_features[6] += 0.4

# Полное совпадение улицы
modified_features[1] += 0.3
modified_features[4] += 0.2

# Совпадение первых символов названия улицы
modified_features[1] += 0.2
modified_features[4] += 0.1

# Разные первые буквы улицы
modified_features[1] *= 0.3
modified_features[4] *= 0.3
```

### Итоговая формула `hybrid_score`

```text
hybrid_score = Σ(feature[i] × weight[i]), i = 1..10
```

Результат ограничивается диапазоном:

```python
score = sum(f * w for f, w in zip(modified_features, weights))
return min(1.0, score)
```

### Сквозной пример

**Запрос пользователя:**

```text
Фабрициуса, 38к2
```

**Кандидат из базы:**

```text
улица Фабрициуса, дом 38, корпус 2
```

**Пошаговый расчет признаков:**

| № | Признак | Значение | Расчет | Результат |
|---|----------|----------|---------|-----------|
| 1 | `ratio_norm` | 85% | `"фабрициуса дом 38 корпус 2"` vs `"улица фабрициуса дом 38 корпус 2"` | 0.85 × 0.20 = **0.17** |
| 2 | `ratio_street` | 100% | `"фабрициуса"` vs `"фабрициуса"` | 1.00 × 0.15 = **0.15** |
| 3 | `token_sort_ratio` | 100% | После сортировки слова совпадают | 1.00 × 0.10 = **0.10** |
| 4 | `partial_ratio` | 100% | `"фабрициуса"` входит полностью | 1.00 × 0.05 = **0.05** |
| 5 | `phonetic_ratio` | 100% | `"fabritsiusa"` vs `"fabritsiusa"` | 1.00 × 0.05 = **0.05** |
| 6 | `prefix_match` | 100% | Первые 5 букв: `"фабри"` совпадают | 1.00 × 0.05 = **0.05** |
| 7 | `house_match` | 100% | `"38к2"` vs `"38к2"` | 1.00 × 0.20 = **0.20** |
| 8 | `corpus_match` | 100% | У обоих есть корпус | 1.00 × 0.05 = **0.05** |
| 9 | `length_ratio` | 65% | `"фабрициуса 38к2"` (17 символов) vs `"улица фабрициуса дом 38 корпус 2"` (44 символа) | 0.65 × 0.05 = **0.033** |
| 10 | `type_match` | 0% | В запросе нет типа улицы, в базе есть `"улица"` | 0.00 × 0.10 = **0.00** |

**Итоговый hybrid_score:**

```text
0.17 + 0.15 + 0.10 + 0.05 + 0.05 + 0.05 + 0.20 + 0.05 + 0.033 + 0.00 = 0.853
```

### Использование в итоговом скоринге

После вычисления `hybrid_score` (взвешенной суммы признаков) система объединяет его с двумя другими метриками для получения финальной оценки кандидата.

---

## Три компонента итогового скора

| Компонент | Описание | Диапазон | Источник |
|-----------|----------|----------|----------|
| **Fuzzy Score** | Результат нечеткого сравнения строк (RapidFuzz) | 0–100% | `fuzzy_search()` |
| **ML Score** | Вероятность от модели логистической регрессии | 0–1 | `model.predict_proba()` |
| **Hybrid Score** | Взвешенная сумма 10 адресных признаков | 0–1 | `calculate_hybrid_score()` |

---

## Формула для обычных кандидатов (не точное совпадение)

```python
final_score = 0.25 * (fuzzy_score / 100) + ml_weight * ml_score + 0.40 * hybrid_score
```

**Коэффициенты:**

| Коэффициент | Вес | Назначение |
|-------------|-----|------------|
| `0.25` | 25% | Вклад нечеткого поиска |
| `ml_weight` | 15–35% | Вклад ML-модели (зависит от уверенности) |
| `0.40` | 40% | Вклад адресных правил (наибольший вес) |

**Адаптивный вес ML (`ml_weight`):**

```python
if ml_score > 0.3:
    ml_weight = 0.35   # ML-модель уверена → высокий вес
else:
    ml_weight = 0.15   # ML-модель сомневается → низкий вес
```

---

## Формула для точных совпадений (найдены по индексу)

Когда адрес найден через хэш-индекс (`exact_match = True`):

```python
final_score = 0.8 + 0.2 * hybrid_score
```

**Диапазон:** от 0.8 (если `hybrid_score = 0`) до 1.0 (если `hybrid_score = 1`)

Такие кандидаты считаются очень надежными и получают высокую базовую оценку.

---

## Примеры расчета `final_score`

### Пример 1: Хороший кандидат

| Компонент | Значение |
|-----------|----------|
| `fuzzy_score` | 85% |
| `ml_score` | 0.75 (>0.3 → ml_weight = 0.35) |
| `hybrid_score` | 0.85 |

**Расчет:**

```text
final_score = 0.25 × (85/100) + 0.35 × 0.75 + 0.40 × 0.85
            = 0.25 × 0.85 + 0.35 × 0.75 + 0.40 × 0.85
            = 0.2125 + 0.2625 + 0.34
            = 0.815
```

**Результат:** 81.5% — высокая уверенность ✅

---

### Пример 2: Плохой кандидат

| Компонент | Значение |
|-----------|----------|
| `fuzzy_score` | 45% |
| `ml_score` | 0.20 (≤0.3 → ml_weight = 0.15) |
| `hybrid_score` | 0.35 |

**Расчет:**

```text
final_score = 0.25 × (45/100) + 0.15 × 0.20 + 0.40 × 0.35
            = 0.25 × 0.45 + 0.15 × 0.20 + 0.40 × 0.35
            = 0.1125 + 0.03 + 0.14
            = 0.2825
```

**Результат:** 28.3% — низкая уверенность ❌ (отклоняется, так как порог 0.4)

---

### Пример 3: Точное совпадение по индексу

| Компонент | Значение |
|-----------|----------|
| `exact_match` | True |
| `hybrid_score` | 0.95 |

**Расчет:**

```text
final_score = 0.8 + 0.2 × 0.95 = 0.8 + 0.19 = 0.99
```

**Результат:** 99% — почти идеальное совпадение ✅

---

## Пороги принятия решений

| `final_score` | Решение |
|---------------|---------|
| `≥ 0.6` | Высокая уверенность — автоматический выбор |
| `0.4–0.6` | Средняя уверенность — показываем варианты пользователю |

# Логика обработки «пр»

## Логика обработки "пр" (проспект / проезд)

Аббревиатура `"пр"` в адресах может означать как **проспект**, так и **проезд**. Система различает эти варианты с помощью четырёхшагового алгоритма, где каждый следующий шаг обрабатывает только те случаи, которые не были покрыты предыдущими.

---

### ШАГ 1: `"пр-д"` — ВСЕГДА "проезд"

Если в адресе встречается сокращение `"пр-д"` или `"пр-д."` (с дефисом и буквой `"д"`), оно однозначно обозначает **проезд**. Это самый приоритетный шаг.

```python
address = re.sub(r'\bпр-д\b', r'проезд', address, flags=re.IGNORECASE)
address = re.sub(r'\bпр-д\.', r'проезд', address, flags=re.IGNORECASE)
```

| Вход | Выход |
|-------|--------|
| `"пр-д 123"` | `"проезд 123"` |
| `"пр-д. 123"` | `"проезд 123"` |
| `"Пр-д Строителей"` | `"проезд строителей"` |

---

### ШАГ 2: `"([а-я]+) (м|м.) пр."` → `"малый \1 проезд"`

Если перед `"пр"` или `"пр."` стоит название (например, `"Коптевский"`) и указатель размера `"М."` (малый) или `"Б."` (большой), то это **проезд**. Система переставляет слова: размер переносится перед названием, а `"пр"` заменяется на `"проезд"`.

```python
address = re.sub(
    r'([а-я]+)\s+(м|м\.)\s+пр\.?\b',
    r'малый \1 проезд',
    address,
    flags=re.IGNORECASE
)

address = re.sub(
    r'([а-я]+)\s+(б|б\.)\s+пр\.?\b',
    r'большой \1 проезд',
    address,
    flags=re.IGNORECASE
)
```

| Вход | Выход |
|-------|--------|
| `"Коптевский М. пр. 4"` | `"малый коптевский проезд 4"` |
| `"Петровский Б. пр."` | `"большой петровский проезд"` |
| `"Коптевский М пр 4"` | `"малый коптевский проезд 4"` |

---

### ШАГ 3: `"(\d+)-[яй] пр."` → `"\1-й проезд"`

Если перед `"пр"` или `"пр."` стоит порядковое числительное (`1-й`, `2-я`, `3-е`), то это **проезд**. Система заменяет `"пр"` на `"проезд"`, сохраняя числительное.

```python
address = re.sub(
    r'(\d+)-[яй]\s+пр\.?\b',
    r'\1-й проезд',
    address,
    flags=re.IGNORECASE
)
```

| Вход | Выход |
|-------|--------|
| `"1-й пр. 11"` | `"1-й проезд 11"` |
| `"2-я пр. 5"` | `"2-й проезд 5"` |
| `"3-е пр."` | `"3-й проезд"` |

---

### ШАГ 4: Все остальные `"пр"` и `"пр."` → `"проспект"` (по умолчанию)

Если ни одно из предыдущих условий не выполнилось, `"пр"` или `"пр."` интерпретируется как **проспект**. Это значение по умолчанию.

```python
address = re.sub(
    r'\bпр\.?\b',
    r'проспект',
    address,
    flags=re.IGNORECASE
)
```

| Вход | Выход |
|-------|--------|
| `"пр. Ленина"` | `"проспект ленина"` |
| `"Ленина пр."` | `"ленина проспект"` |
| `"пр Мира"` | `"проспект мира"` |

---

## Формула расчета баллов

Баллы используются для ранжирования кандидатов внутри округа. Чем выше балл, тем более релевантен адрес.

### Базовый расчет

```text
BASE_SCORE =
    len(keywords)
  + len(ordinals)
  + len(simple_numbers)
  + len(context_numbers)
  + len(letters_numbers)
```

| Компонент | Описание | Пример |
|-----------|----------|---------|
| `len(keywords)` | Количество ключевых слов в запросе | `["троицк", "микрорайон", "дом", "8"]` → 4 |
| `len(ordinals)` | Количество порядковых числительных | `"6-я"` → 1 |
| `len(simple_numbers)` | Количество простых чисел | `"8"` → 1 |
| `len(context_numbers)` | Количество чисел с контекстом | `"дом=8"` → 1 |
| `len(letters_numbers)` | Количество чисел с буквами | `"13б"` → 1 |

### Бонусы

| Условие | Бонус | Описание |
|----------|--------|-----------|
| `settlement_match` | +20 | Найден населенный пункт из `SETTLEMENT_REF` |
| `municipality_match` | +15 | Найдено муниципальное образование из `MUNICIPALITY_REF` |
| `house_number_match` | +30 | Номер дома полностью совпадает |
| `microdistrict_match` | +25 | Название микрорайона совпадает |

### Итоговая формула

```text
TOTAL_SCORE = BASE_SCORE + Σ(БОНУСЫ)
```

# Система кэширования

## Назначение

Система кэширования предназначена для ускорения повторных запусков программы. При первом запуске выполняются:

- Нормализация всех адресов
- Создание хэш-индекса для быстрого поиска

Эти операции занимают **~3 минуты**. При последующих запусках результат загружается из кэша за **~2–3 секунды**. (На основе данных из 500000 адресов)

---

## Структура кэша

```text
address_matcher/
└── cache/
    ├── precomputed_a1b2c3d4e5f6.pkl    # кэш для текущей версии кода
    ├── precomputed_f6e5d4c3b2a1.pkl    # кэш для предыдущей версии
    └── ...                             # старые кэши (можно удалить)
```

Файлы кэша хранятся в папке `cache/` (добавлена в `.gitignore`).

---

## Что хранится в кэше

```python
cache_data = {
    'normalized_addresses': [...],       # все нормализованные адреса)
    'index': {...},                      # хэш-индекс для быстрого поиска
    'created_at': '2024-01-01T12:00:00', # дата создания
    'cache_version': 2,                  # версия кэша (увеличивается вручную)
    'num_addresses':               # количество адресов в базе
}
```

---

## Расчет хэша

Имя файла кэша формируется на основе хэша, который учитывает:

```text
HASH = MD5(
    CACHE_VERSION +                    # ручная версия (увеличивается при форс-пересборке)
    MD5(src/utils.py) +                # содержимое файла нормализации
    MD5(src/street_variants.py) +      # содержимое файла реверса слов
    MD5(src/tinao.py) +                # содержимое файла ТиНАО
    MD5(src/zelao.py) +                # содержимое файла ЗелАО
    len(addresses) +                   # количество адресов в базе
    mtime(addresses.csv)               # дата последнего изменения базы
)
```

**Таким образом, при изменении любого из этих параметров хэш меняется, и кэш пересоздается автоматически.**

---

## Когда кэш пересоздается автоматически

| Изменение | Пересоздание | Причина |

# Файловый режим обработки

## Назначение

Файловый режим позволяет обогатить пользовательский файл с адресами данными из основной базы. Для каждой строки файла программа находит соответствующий адрес в базе и добавляет:

- **УНОМ** — уникальный идентификатор адреса
- **Все остальные колонки** из базы (район, округ, количество лифтов, жителей, год постройки и т.д.)

---

## Поддерживаемые форматы

| Формат | Расширение | Требуемая библиотека |
|---------|------------|---------------------|
| CSV | `.csv` | встроенная в pandas |
| Excel | `.xlsx` | `openpyxl` |
| Excel (старый) | `.xls` | `openpyxl` |

**Установка для Excel:**

```bash
pip install openpyxl
```

---

## Требования к входному файлу

### Обязательные условия

1. **Имя файла:** `Data` (без учета регистра)
2. **Расположение:** папка `data/`
3. **Обязательная колонка:** `Адрес` (в любом регистре)

### Опциональные колонки

| Колонка | Назначение |
|----------|------------|
| `Округ` | Для автоматического добавления ключевых слов (ТиНАО/ЗелАО) |
| `Район` | Если есть — будет заполнена из базы |
| `УНОМ` | Если есть — будет перезаписана актуальными данными |

### Пример структуры файла

| Адрес | Округ | Район |
|--------|--------|--------|
| улица Фабрициуса, 38к2 | СЗАО | |
| Зеленоград, корпус 1601 | ЗелАО | |
| Тверская ул., д. 10 | ЦАО | |

## Автоматическое добавление ключевых слов

Если во входном файле присутствует колонка `Округ`, программа автоматически добавляет ключевые слова к поисковому запросу.

### Правила для ТиНАО

| Значение в колонке "Округ" | Действие |
|----------------------------|----------|
| `ТиНАО` | добавить `тинао` |
| `Троицк` | добавить `тинао` |
| `Троицкий` | добавить `тинао` |
| `Новомосковский` | добавить `тинао` |

### Правила для ЗелАО

| Значение в колонке "Округ" | Действие |
|----------------------------|----------|
| `ЗелАО` | добавить `зеленоград` |
| `Зеленоград` | добавить `зеленоград` |

### Пример

**Входная строка:**

```text
Округ = "ТиНАО"
Адрес = "3-я Нововатутинская ул., д. 13, к. 2"
```

**Поисковый запрос:**

```text
тинао 3-я Нововатутинская ул., д. 13, к. 2
```

**Результат:** адрес успешно находится в базе ТиНАО.
